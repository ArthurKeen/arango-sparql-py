  - **`EngineProviderBridge`** — adapts `LLMClient.generate(messages)` to the
    engine's `LLMProvider.generate(system, user) -> (content, usage_dict)`.

## Key design decision (resolver injection)
`SparqlAdapter.__init__(*, resolver, ontology_ttl="")` **decouples** the two
inputs: `resolver` is the caller's already-built object (validate() uses it);
`ontology_ttl` feeds ONLY the prompt. It never rebuilds a resolver from
`ontology_ttl`. The negative-control test makes the divergence concrete: over
`MAPPING_ONTOLOGY` (`:Widget → phys:collectionName "PhysWidgets"`), the
populated resolver yields AQL containing `PhysWidgets` and `validate()` returns
`ok=True`, whereas an empty-graph resolver (what a blank `ontology_ttl` would
rebuild) *raises* `SchemaResolutionError` → `ok=False`. A monkeypatch identity
spy additionally proves `validate()` forwards the exact injected resolver.
