# Phase 06.1 — Plan 03 Summary (the re-point) + behavior-preservation gate

**Status:** complete. All gates green.

## What changed
- `arango_sparql/nl2sparql/pipeline.py`:
  - `NlPipeline.run()` no longer drives its private `PromptBuilder → LLMClient →
    RepairLoop` loop. It now constructs `EngineProviderBridge(self.client)` +
    `SparqlAdapter(resolver=self.resolver, ontology_ttl=self.ontology_ttl)` and
    an `NLQueryEngine(provider=…, adapter=…, few_shot_k=0,
    max_retries=self.repair_loop.max_repairs)`, calls `engine.generate(nl)`,
    and maps `NLResult → PipelineOutcome`.
  - The engine call is wrapped in `try/except Exception` so a bridge-re-raised
    transport failure degrades to a `W_NL_TRANSLATION_FAILED` outcome.
  - On `result.ok`, the final query is re-translated ONCE (with `params`) to
    recover `aql`/`bind_vars`/warnings. `repaired = result.retries > 0`; when
    repaired, `W_NL_REPAIRED` is appended.
  - `explain()`, `_translate_only()`, `_call_llm_raw()`, `_success_outcome()`,
    `_failure_outcome()` are unchanged; `/nl-explain` never routes through the
    engine. `_call_llm` + `PromptBuilder`/`RepairLoop` wiring are left dormant
    (not deleted), keeping their imports live.
  - Module docstring documents the cost/audit **option (b)** decision and the
    accepted retry-prompt-wording deviation (Plan 03 Task 2).
- `tests/nl2sparql/test_pipeline.py`: all existing assertions preserved, plus
  two new regression tests — mapping-only resolver parity and params-conflict
  graceful failure.

## Decisions / deviations
- **Fence extraction kept faithful (not merely "accepted").** The engine's
  `_strip_code_fence` only strips when the completion *starts* with a fence,
  which broke the existing unit tests' `"Here you go:\n\n```sparql…"` shape.
  Fix: `EngineProviderBridge.generate` runs the completion through the
  standalone `extract_sparql_from_response` before returning, so the engine's
  stripper sees clean SPARQL (no-op). This preserves standalone extraction
  semantics exactly. Only the engine's retry-prompt *wording* remains an
  accepted, non-gating live-model deviation (the repair *hint* text is
  byte-identical via `format_repair_context`).
- **Params-conflict guard catches `ValueError` too.** The plan assumed a
  reserved bind name raises `SparqlError`, but the AQL builder raises
  `ValueError` at compose time. The final re-translate is therefore guarded by
  two `except` clauses (`SparqlError` and `ValueError`) so run() never raises —
  honoring the plan's never-raise intent and closing a latent crash path the
  original pipeline also had. (`except SparqlError` is present verbatim.)
