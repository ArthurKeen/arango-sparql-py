# Spike findings — CK25 execution grading (pre-plan evidence)

Ran during the 07.1→07.2 transition to de-risk the phase. This is the empirical
basis for 07.2's decisions. Everything below was executed against the live repo.

## Problem (the trigger)

07.1 wired QALD-9-plus + CK25 into the harness, but the only recorded numbers are
`scripted-*` (gold fed back as model output → measures gold-transpilability, not
model accuracy). Running the **real** `openai-gpt4o-mini` model against them exposed
that the **canonical exact-algebra judge floors real output at 0%**:

- `openai-gpt4o-mini-ck25`: canonical **0/49**, but **48/49 transpiled** (1 refusal).
- `openai-gpt4o-mini-qald9plus` (25-case sample): canonical **0/25**, **24/25 transpiled**.

Root cause: the adopted golds pre-resolve entities to literal IRIs
(`<...empl-Karen.Brant%40company.org>`, `res:Skype`, `res:Area_51`) and fix a
`?result` projection the model can't infer from NL + schema alone. The model instead
writes valid name/class-pattern queries → structurally different → canonical judge = fail.
Exact-match SPARQL judging is the wrong instrument for adopted benchmarks (it was
correct for the hand-authored seed corpus whose golds were written to be reproducible).

## What the spike did

1. Fetched the **full CK25 instance graph** (not the schema-only extract 07.1 vendored):
   - Source: `https://github.com/eccenca/ck25-dataset` → `graphs/prod-inst.ttl`
   - Commit: `cb928b2f201e4bdbbde9a1cd0653152779736395` (same commit 07.1 pinned)
   - 951 KB, **26,903 triples** loaded into pyoxigraph; 1,109 employee-instance refs.
2. **Data sanity:** all 8 sampled gold queries return non-empty answers against the
   instance graph (the data genuinely answers the questions).
3. Built a value-set execution judge (throwaway, in scratchpad): run gold + model
   SPARQL through pyoxigraph, compare the **multiset of frozenset-of-values-per-row**
   (answers up to variable renaming). Ran the live model over all 49 CK25 cases.

## Result

| Judge | CK25 (N=49) |
|-------|-------------|
| Canonical (exact-algebra, today's default) | **0/49 = 0%** |
| Execution (answer-set, var-rename-insensitive) | **4/49 = 8.2%** (lower bound) |

Confirmed matches: ck25-3, ck25-30, ck25-39 (485 rows exact), ck25-50.

## What the per-case data taught us (feeds the plan)

1. **Dominant miss = `gold=Nr model=0r`** — the model writes valid SPARQL that returns
   ZERO rows: it guesses entity name literals / predicates that don't exist verbatim in
   the data. This is a *real* capability gap (correctly measured now), not a judge artifact.
   It's exactly what CK25-as-anchor is meant to expose.
2. **True number is higher than 8.2%** — ck25-31 (26/26 rows) and ck25-32 (246/246 rows)
   return the right cardinality but "diff" values: the model projects a **label** where
   gold projects an **IRI**. ⇒ **IRI↔label normalization is required** and lifts the score.
   (Motivates the 07.2 correctness decision.)
3. **Three gaps are judge/engine issues, NOT the model** — a production execution judge
   MUST handle these:
   - **ASK queries** (ck25-16/28/33): pyoxigraph returns `QueryBoolean`, not bindings —
     the judge needs an ASK branch (compare the boolean).
   - **`xsd:int()` casts** (ck25-37/42): the *gold* uses a function pyoxigraph rejects
     (`custom function xsd:int not supported`) — needs normalization or a documented skip.
   - **3 model queries the transpiler accepted but pyoxigraph rejected** (ck25-5/18/26,
     SyntaxError near `%`-encoded IRI / prefix) — our transpiler is more lenient than
     oxigraph's parser; the judge must classify these (model-error vs engine-limitation).

## Implications locked into 07.2

- Execution judging **works** and is tractable for CK25 (one data file + ~40 lines).
- Decisions (see 07.2-CONTEXT.md): CK25 now / QALD later; **pyoxigraph only**;
  correctness = answer-set match up to var-rename **+ IRI↔label normalization**.
- The clean CK25 number (post-ASK + IRI/label handling) is expected in the ~10–16% range —
  a legitimate, useful corporate-domain anchor reading (reported, not gated).
