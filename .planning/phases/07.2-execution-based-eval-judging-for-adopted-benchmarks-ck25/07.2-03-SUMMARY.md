## Decisions Made
- **Discriminating-check candidate substitution.** The plan's literal Task-2 `<automated>` script constructs its discriminating candidate via a blanket `gold.replace('?', '?z_')` variable rename. Running it verbatim raised `AssertionError: canonical should reject the renamed clone` — NOT because the execution judge silently fell through to canonical, but because `_judge_canonical`'s alpha-normalization (`_alpha_normalize` in `runner.py`, added by `fix(06.2-04): make canonical judge alpha-equivalent (variable renaming)`, which predates this phase entirely) already treats a pure variable rename as canonically equal. Verified empirically that both a blanket rename AND a triple-reorder are accepted by `_judge_canonical` on this codebase (`_canonical(gold) == _canonical(renamed)` and `_canonical(gold) == _canonical(reordered)` both `True`). Since the plan's own stated INTENT ("a silently-still-canonical regression fails the gate") requires a candidate the two judges genuinely diverge on, substituted an IRI<->label lookup swap for `ck25-1` (the execution judge's actual distinguishing feature per D-03) — this is accepted by execution and rejected by canonical, satisfying the gate's purpose even though it isn't the exact script text in the plan.
- Appended (never replaced) the baseline note's existing sentence, preserving RESEARCH Pitfall 3's "only judge-dependent fields may change" discipline; `pass_rate`/`passed`/`total`/`role`/`surviving_n`/`achieved_mde` all stayed 1.0/49/49/anchor_reported_not_gated/49/unchanged since gold-vs-gold under execution measures identically to the prior canonical-judged number for this fully-symmetric-text corpus.

- **Verification:** Re-ran `run('scripted-ck25').pass_rate` → `1.0` (49/49), zero failing cases; `pytest tests/nl2sparql/eval/test_judge_execution.py tests/nl2sparql/eval/test_judge.py -q` → 12 passed; `ruff format --check` + `ruff check` on `runner.py` clean.
