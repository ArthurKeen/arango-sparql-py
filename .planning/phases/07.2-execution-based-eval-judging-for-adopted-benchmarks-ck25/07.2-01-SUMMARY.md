# Phase 07.2 Plan 01: Execution-based answer-set judge Summary

**Built a var-rename- and IRI<->label-insensitive pyoxigraph execution judge with ASK support, safe gold-side `xsd:int` normalization, distinctly-tagged gold/candidate engine-exception buckets, and a 4-arg `_judge` dispatcher that fixes a blocker where CK25's corpus-level (not per-case) instance-graph fixture could never reach the execution path.**

## Performance

- **Duration:** ~45 min
- **Tasks:** 3
- **Files modified:** 4 (1 created, 3 modified)

## Accomplishments
- `tests/nl2sparql/eval/test_judge_execution.py`: six no-network unit tests (ASK boolean compare, var-rename + duplicate-safe row match, IRI<->label normalization, gold `xsd:int` normalization, tagged gold/candidate engine exceptions, and a discriminating test proving the 4-arg dispatcher actually fires the execution judge instead of silently falling through to canonical).
- `tests/helpers/oxi.py`: `oxi_query(store, sparql) -> OxiQueryResult` branches on the actual Python type `store.query()` returns (`QueryBoolean` vs `QuerySolutions`), never on SPARQL text; lets `SyntaxError`/`RuntimeError` propagate for the judge to classify.
- `tests/nl2sparql/eval/runner.py`: `_judge_execution` now returns `(passed, judge_note)`, using a sorted-tuple-per-row multiset comparison with `rdfs:label` normalization for SELECT, boolean comparison for ASK, separate gold/candidate exception handling with distinct `judge_note` tags, and the gold-only `xsd:int(`->`xsd:integer(` pre-pass. `_judge` grows a 4th `data_ttl=None` arg whose guard fires on the corpus-level fixture (BLOCKER fix). `run()` reads an optional corpus-level `data_path` once per run and threads it through every case.
- `tests/nl2sparql/eval/test_corpus_schema.py`: updated the three now-tuple-returning `_judge(...)` identity assertions to unpack `[0]`; no other test in that file touched.

## Decisions Made
- IRI↔label and literal normalization both route through the same `_strip_execution_literal` helper so a gold's IRI-normalized-to-label value and a candidate's raw quoted-literal value land on identical plain text before comparison (discovered while making `test_iri_label_normalization` and the discriminating test pass — the first implementation attempt only stripped IRIs, leaving quoted literals unstripped, causing a spurious mismatch).
- Kept `_judge_canonical`'s own signature/return type (`bool`) unchanged — only `_judge`'s wrapping return type changed to a tuple, per the plan's exact scope.

- **Found during:** Task 3 (making `test_iri_label_normalization` and `test_execution_judge_fires_not_silently_canonical` GREEN)
- **Issue:** RESEARCH's `normalize_value` sketch only strips the `<iri>` wrapper and otherwise returns raw values verbatim; a candidate literal like `"Alice"` (quoted, pyoxigraph's N-Triples envelope) would never equal a gold IRI normalized through the label map to the unquoted text `Alice`.
