<objective>
Capture the **genuine live-model baseline** — the whole point of the phase: a number with
headroom that Phase 7's few-shot lift can be measured against. Write a reproducibility
runbook (`README.md`) documenting the exact credentials-gated steps, then (via a human
checkpoint, because the live sweep needs a provider key the agent must never hold) capture
the `openai-gpt4o-mini` run against the harder corpus and fold its aggregate + per-case
numbers into `baseline.json` as a credentials-gated companion to `scripted`, recording
`model` + `temperature` (0.1) + `corpus_sha` for reproducibility. Add a no-network
structural test that validates the live companion (via `BaselineConfig`) and asserts the CI
eval gate still executes ONLY the scripted config.

Purpose: NL-EVAL-04 SC3/SC4 — a real, reproducible, credentials-gated live baseline with no
secrets committed and scripted staying the no-network CI default. This is the measurable
floor Phase 7 proves a lift over.
Output: `README.md` runbook, an `openai-gpt4o-mini` entry in `baseline.json`, and a
structural test.

Guardrails to honor exactly (AI-SPEC §6): (1) the runner's live path reads
**NL2SPARQL_API_KEY**, not OPENAI_API_KEY (Pitfall 1) — a missing key 401s loudly, it does
not fall back; (2) `write_report()` emits a DIFFERENT flat schema
(`{config,pass_rate,cases:[{name,passed,elapsed_ms}]}`) into gitignored `reports/` — folding
its numbers into `baseline.json`'s nested `{configs:{...}}` shape is a MANUAL, human-reviewed
step, never auto-regenerated in CI (Pitfall 2); (3) only aggregate numbers + model +
temperature + corpus_sha are committed — raw prompts/completions (which embed the ontology
and could embed a mistakenly-pasted key) stay in gitignored `reports/`; (4) transpiler
untouched — W3C ≥ 96.4% preserved.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env `NL2SPARQL_API_KEY` (secret) → live sweep | The key must never enter the repo, logs, or committed artifacts |
| gitignored `reports/` (raw prompts/completions) → committed `baseline.json` | Only aggregate numbers may cross; raw payloads (ontology, possible pasted key) must not |
| live config → default pytest path | The live provider must never be reachable from key-free CI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06.2-09 | Information disclosure | Provider key committed into baseline.json / README / a report | mitigate | Only aggregate numbers + model/temperature/corpus_sha committed; `grep` secret-scan gate; raw payloads stay in gitignored `reports/`; checkpoint instructs human never to paste the key |
| T-06.2-10 | Information disclosure | Raw request/response bodies (embed ontology + possible pasted key) leaking into a committed file | mitigate | `write_report` writes only to gitignored `reports/`; fold-in copies numbers only, never payloads |
| T-06.2-11 | Denial of service / degradation | Live provider called on the key-free CI default path | mitigate | Live config only via non-scripted config behind `RUN_EVAL=1` + key; new structural test is no-network and asserts CI executes only `run('scripted')` |
| T-06.2-12 | Spoofing | Missing key silently degrading to an empty-bearer 401 masked as a low score | mitigate | Runner reads `NL2SPARQL_API_KEY` and 401s loudly (fail-fast, no fallback); runbook documents the failure mode |
| T-06.2-SC | Tampering | npm/pip/cargo installs | accept | No package installs this plan — `uv sync --extra nl` resolves already-pinned deps only |
</threat_model>
