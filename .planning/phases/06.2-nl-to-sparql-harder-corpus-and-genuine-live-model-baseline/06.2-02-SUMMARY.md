## Decisions Made
- **`:placed`/`:knows` are dedicated edge collections, not attribute joins.** The committed Task-1 ontology comment asserted a bare `owl:ObjectProperty` becomes an attribute join like `hybrid.yml`; that is false — `hybrid.yml` achieves the attribute join by leaving the predicate *undeclared* (local-name fallback), whereas an *explicit* `owl:ObjectProperty` routes to edge traversal and requires `phys:edgeCollectionName` or it raises `SchemaResolutionError`. Chose the `edge_traversal.yml` DEDICATED_COLLECTION idiom (add `phys:edgeCollectionName`) because the plan's Task-1 action explicitly says to declare an object property "with whatever phys mapping edge_traversal.yml/hybrid.yml shows is needed to transpile"; this makes `:knows` a real graph edge (the textbook property-path subject) and every path/aggregation/multi-hop gold transpiles.
- **Transitive paths use the default max depth (10).** No `property_path_max_depth` knob override in the golds (the depth-2 overrides in `property_paths.yml` exist only to keep those goldens short).
- **New positives leave `scripted` unset** so they replay their own gold and pass the canonical judge trivially (positives; headroom is a live-config property).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `:placed`/`:knows` object properties did not transpile**
- **Found during:** Task 3 (and surfaced by the Task-1 guard on the pre-existing `orders-per-person` case)
- **Issue:** The committed Task-1 ontology declared `:placed`/`:knows` as bare `owl:ObjectProperty` with no `phys:edgeCollectionName`. The transpiler raises `SchemaResolutionError` ("object property … has no phys:edgeCollectionName annotation") for such properties in a hop context, so `orders-per-person` and every planned property-path/multi-hop gold using them would transpile to nothing and be permanently un-judgeable (exactly the AI-SPEC Pitfall 4 the guard exists to catch).
- **Fix:** Added `phys:edgeCollectionName "placed"` / `phys:edgeCollectionName "knows"` (edge_traversal.yml DEDICATED_COLLECTION idiom) and rewrote the two ontology comments that falsely described an attribute join.
- **Files modified:** tests/nl2sparql/eval/corpus.yml
- **Verification:** `RUN_EVAL=1 pytest tests/nl2sparql/eval/test_gold_transpilable.py -q` → 22 passed (was 1 failed before the fix).
- **Committed in:** `2dd52d9`
