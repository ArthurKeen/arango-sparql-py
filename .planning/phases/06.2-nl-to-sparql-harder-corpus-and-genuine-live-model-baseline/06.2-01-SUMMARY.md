**CorpusCase/BaselineConfig Pydantic load-time gate that fails the corpus load on a malformed positive gold (never silently skips), plus an inverted `expect_refusal` judge branch scoring negatives as PASS iff the pipeline emits no transpilable AQL.**

## Accomplishments
- `CorpusCase` Pydantic model with a `_gold_must_parse` `model_validator` that runs `parse_sparql` on every positive gold and re-raises `SparqlParseError` as a `ValidationError` — a malformed gold now fails the load loudly (AI-SPEC Critical Failure Mode 2 closed; threat T-06.2-01 mitigated).
- `BaselineConfig` Pydantic model with a bounded `pass_rate` (`[0,1]`) plus the optional live-reproducibility fields `model`/`temperature`/`corpus_sha` so Plan 04 can fold a live-model run into `baseline.json` without re-touching `runner.py`.
- Inverted `expect_refusal` branch in `_judge`: negatives PASS iff `outcome.aql == ""`, FAIL on a confident query over invented terms (threat T-06.2-02 mitigated).
- `_load_corpus` now constructs a `CorpusCase` per entry as a load-time gate while keeping `run()`'s existing `case[...]` dict access unchanged.
- New hermetic, eval-marked, `RUN_EVAL`-gated regression test file (9 tests, no network, no `corpus.yml` read).

## Decisions Made
- **`expect_refusal` pinned as the exact marker key** — the corpus data, the `CorpusCase` field, and the `_judge` branch all key on the same string so the negatives contract has one source of truth.
- **Validator skips parsing for refusal cases** — for `expect_refusal: true`, `expected` holds a human-readable rationale (AI-SPEC §5), so the gold-must-parse check only runs for positives.
- **Gate discards the model, keeps the dict** — `_load_corpus` validates then returns the raw YAML dict so `run()` is untouched (minimal blast radius, no data-flow rewrite).
