# Phase 06.2 Plan 04: Live-model baseline + alpha-equivalent judge Summary

**Captured a genuine, reproducible, credentials-gated live-model baseline (`openai-gpt4o-mini`, pass_rate 0.32 / 8-of-25, temperature 0.1, corpus_sha `d3d3806`) — after discovering during the live sweep that the canonical judge was variable-name sensitive (correct-but-renamed answers scored 0/25) and fixing it to be alpha-equivalent, which is the difference between a meaningful baseline and a Phase-7 lift that would be faked by variable-name copying.**

## Performance
- **Duration:** ~40 min (autonomous tasks + human live sweep + judge fix + re-sweep + fold-in)
- **Tasks:** 3 (Task 1 autonomous; Task 2 human-action live sweep; Task 3 autonomous structural test + fold-in) + 1 in-flight judge correctness fix
- **Files:** README.md (new), test_judge.py (new), test_eval.py, runner.py, baseline.json

## Accomplishments
- **Live-model baseline (NL-EVAL-04):** `configs['openai-gpt4o-mini']` in `baseline.json` — `pass_rate 0.32` (8/25), `model gpt-4o-mini`, `temperature 0.1`, `corpus_sha d3d3806`, all 25 cases tracked. Genuine headroom: the model passes easy BGP + several aggregation/OPTIONAL cases but misses property paths, per-key aggregation, and the honest-refusal negatives (it hallucinates a query instead of refusing) — exactly the room a Phase-7 few-shot pass must prove it can lift.
- **Reproducibility runbook** (`README.md`): `uv sync --extra nl`, the key-free scripted CI default, the credentialed live sweep via `NL2SPARQL_API_KEY` (explicitly *not* `OPENAI_API_KEY`), `corpus_sha` capture, the manual human-reviewed fold-in, secret/payload hygiene, and the headroom check.
- **No-network guards** (`test_eval.py`): `test_live_baseline_companion_structural` validates the companion via `BaselineConfig` (model, temperature==0.1, corpus_sha, `0<pass_rate<1`, case-set parity) and now runs (no longer skips) with the entry present; `test_ci_gate_only_ever_runs_scripted` statically asserts the eval gate only ever calls `run("scripted")`.
- **Alpha-equivalent canonical judge** (`runner.py`, `test_judge.py`): `_alpha_normalize` renames all rdflib `Variable`s to `?v0/?v1/...` by first occurrence in a structure-driven, name-independent walk (set elements ordered by a name-erased `_skeleton`); wired into `_canonical`. Sound — only consistent bijective renamings unify. New fast, no-network `test_judge.py` guards the property on the default path.

## Decisions Made
- **Fix the judge, not the baseline.** The first live sweep returned 0/25 because every semantically-correct answer used different variable names (`?person` vs gold `?s`). Accepting that would have made a meaningless baseline and let Phase-7 "lift" the score by teaching variable-name mimicry. Alpha-equivalence is the correct, sound fix and leaves the scripted verdicts unchanged (scripted replays the gold verbatim).
- **Run-derived fold-in.** The companion entry was built from `reports/openai-gpt4o-mini.json` (the real `write_report` output), not hand-typed — avoiding transcription error and extra API cost.
- **Secret hygiene.** The OpenAI key lives only in the gitignored `.env`; it was aliased to `NL2SPARQL_API_KEY` in-shell for the sweep, never printed or committed. `reports/` is gitignored.

## Deviations from Plan
- **Added an unplanned judge fix (`deb6f13`).** The plan assumed the live sweep would directly yield a headroom number; the sweep instead exposed that `_canonical` was variable-name sensitive. Per the independent audit's NIT #6 (predicted risk) and the "surface don't guess" rule, this was raised to the user, who approved fixing the judge (alpha-equivalence) before promoting a baseline. The fix is confined to `tests/nl2sparql/eval/` (transpiler untouched).

## Issues Encountered
- First live sweep: 0/25 (judge artifact, diagnosed above). After the judge fix, the re-sweep gave 0.32 (8/25) — a meaningful baseline.

## User Setup Required
- To reproduce the live baseline: set `NL2SPARQL_API_KEY` (or, as here, alias it from `OPENAI_API_KEY` in `.env`), then `RUN_EVAL=1 python -c "from tests.nl2sparql.eval.runner import run, write_report; r=run('openai-gpt4o-mini'); write_report(r)"`. CI itself needs nothing — the scripted gate stays key-free and no-network.
