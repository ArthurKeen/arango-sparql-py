<objective>
Grow `corpus.yml` from single-BGP toys to real-difficulty **positive** cases across the
Section-1b difficulty classes that ARE transpilable by this repo's deterministic
transpiler: **OPTIONAL** cardinality (`LeftJoin`), **aggregation / GROUP BY**
(`AggregateJoin`/`Group`), **property paths** limited to the transpilable operators
(SequencePath `:p/:q`, InvPath `^:p`), and **multi-hop** via explicit join chains
(multi-triple BGP). Extend the shared `ontology:` block with the terms these classes
need (an object-property relationship for aggregation/multi-hop, an optional datatype
property for OPTIONAL), mirroring the phys idiom already used in
`tests/translate/{hybrid,edge_traversal}.yml`. Land a permanent **authoring guard**
(`test_gold_transpilable.py`) that asserts every non-refusal gold parses via rdflib AND
transpiles to non-empty AQL.

Purpose: These positive classes give the corpus its difficulty spine and are the cases
the canonical-algebra judge scores directly (NL-EVAL-03 SC1). Every gold is verified
transpilable at authoring time so it can never become un-judgeable (AI-SPEC Pitfall 4 /
Guardrail "Gold transpilability gate"). **Un-transpilable path operators (`+` `*` `|`,
negated paths) are intentionally deferred to Plan 03 as NEGATIVE / unsupported cases** —
they are not authored here. This plan touches ONLY corpus data + a guard test; the
generator and transpiler are untouched (W3C ≥ 96.4% preserved).
Output: an extended `corpus.yml` + a transpilability guard test.
</objective>
