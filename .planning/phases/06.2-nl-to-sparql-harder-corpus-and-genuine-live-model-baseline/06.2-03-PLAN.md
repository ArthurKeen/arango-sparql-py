<objective>
Complete the harder corpus with the **negative / unsupported (honest-refusal)** class and
lock in the regenerated scripted regression gate. Author ≥3 `expect_refusal: true` cases
whose NL asks something the ontology cannot honestly answer (an unanswerable / absent-term
question). Each negative's `scripted:` canned response is authored to trigger a GENUINE
transpiler rejection so `outcome.aql == ""`. The **primary, drift-proof** trigger is a
deliberately **malformed / unparseable SPARQL** scripted response → `SparqlParseError` →
`aql == ""` (invariant to future transpiler capability, and the Plan-01 `CorpusCase` gate
does not parse-check `expected` for `expect_refusal` cases). Secondary genuinely-unsupported
triggers you MAY use are the inverse-arm negated path `!(^:p)` (documented rejection, stable
message "negated property paths with inverse arms"), nested-alternation inside a MulPath
(`:(p|q)+`), or an RPT-subject path — verify each still yields empty AQL. Each negative's
`expected` field holds a short human-readable **rationale** (documentation only — the
`CorpusCase` gate does NOT parse it as gold, per Plan 01), and the inverted judge scores it
PASS deterministically. Retain the existing deliberate
near-miss so the scripted pass_rate stays **meaningfully < 1.0**. Then regenerate
`baseline.json`'s scripted config from the ACTUAL `run("scripted")` output and extend
`test_eval.py` with a scripted-pass_rate-< 1.0 headroom-invariant assertion.

Purpose: Negatives are the single most dangerous deployment mode (silently-wrong-but-
parseable) and the honest-refusal dimension the AI-SPEC scores by the inverted convention
(NL-EVAL-03 SC1). The retained near-miss keeps `baseline.json` a real gate (SC2). The
regenerated baseline is authored from the true run, never aspirational (Phase 6 discipline).
**Transpiler-untouched — W3C ≥ 96.4% preserved.**
Output: negative cases in `corpus.yml`, a regenerated scripted `baseline.json`, and a
tightened `test_eval.py`.

IMPORTANT nuances to honor (do NOT silently work around):
1. **Unmapped-IRI fallback:** this repo's `SchemaResolver` resolves unknown IRIs to a default
   collection with a schema WARNING (not an error), so a merely-unknown-class query STILL
   transpiles to non-empty AQL — an unknown-IRI-only query is NOT a valid refusal trigger.
2. **Most property-path operators are SUPPORTED and transpile** — transitive `:p+`/`:p*`/`:p?`
   (via `_emit_mul_path`), alternative `:p|:q` (via `emit_alternative_path`), and forward
   negated `!:p`/`!(:p|:q)` (via `_emit_negated_path`) all emit non-empty AQL and are Plan 02
   POSITIVES, NOT refusal triggers. The ONLY unsupported path form is the inverse-arm negated
   path `!(^:p)`. Do NOT cite `+`/`*`/`|`/forward-`!:p` as refusal triggers.
Therefore a scripted negative must refuse via a GENUINE transpiler rejection — primarily a
parse error from malformed SPARQL (drift-proof), or one of the verified-unsupported forms in
the objective. The NL may still describe an absent-term question; it is the canned scripted
response that must be transpiler-rejected.
</objective>
