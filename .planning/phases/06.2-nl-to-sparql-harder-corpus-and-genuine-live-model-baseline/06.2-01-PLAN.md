<objective>
Extend the eval harness (`runner.py`) with the two contract-level capabilities the
harder corpus needs before a single new case is authored: (1) a **load-time Pydantic
gate** (`CorpusCase` / `BaselineConfig`) so a malformed or unparseable gold fails the
corpus load instead of being silently skipped (a skipped case is a hidden coverage
hole — AI-SPEC Critical Failure Mode 2), and (2) an **inverted refusal judge branch**
in `_judge` so negative/unsupported cases (marker `expect_refusal: true`) are scored by
the honest-refusal convention: PASS iff the pipeline emits **no** transpilable AQL,
FAIL iff it emits a confident query over invented terms (the silently-wrong-but-parseable
trap). `BaselineConfig` also gains the optional live-baseline reproducibility fields
(`model`, `temperature`, `corpus_sha`) so Plan 04 can fold a live run into `baseline.json`
without re-touching `runner.py`.

Purpose: These are the harness seams every later plan (harder corpus, negatives, live
baseline) builds on. Interface-first: land the contracts before the data. This is an
**eval-hardening** change only — the deterministic generator and SPARQL→AQL transpiler
are NOT touched (NL-EVAL-03, NL-EVAL-04; keeps W3C ≥ 96.4% by construction).
Output: `runner.py` with the Pydantic gate + inverted judge; `test_corpus_schema.py`
proving both.
</objective>
