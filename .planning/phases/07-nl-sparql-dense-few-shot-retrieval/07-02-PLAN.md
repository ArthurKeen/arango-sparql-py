<objective>
Author the curated few-shot bank and its leakage gate. The bank supplies the
question→gold-SPARQL exemplars the dense/BM25 retrievers rank over; the gate proves,
as a committed test, that the bank shares NO case with the held-out eval corpus AND does
not merely sit just outside it as near-clones, so the lift measurement is never
train-on-test and never a proximity artefact (D-01, D-02, B2).

CRITICAL authoring rule (B2): the bank is authored from an INDEPENDENT difficulty-class
spec (basic BGP, OPTIONAL, aggregation, property-path, multi-hop) with `corpus.yml` CLOSED
— the author must NOT read the corpus's questions/expected and hand-tune bank items to
clear the disjointness gate. The gate runs disjointness + similarity as an AFTER-THE-FACT
check; a collision is a signal to re-author, not to nudge a literal.

The bank reuses `corpus.yml`'s `ontology:` Turtle block VERBATIM (same conceptual schema
— that is what lets the bank cover the same difficulty classes without a second schema to
maintain) and uses the `question:` / `query:` keys the shared engine's
`FewShotIndex.from_corpus_files` expects. Because the ontology block is duplicated, the
gate also asserts bank/corpus ontology PARITY so the two copies cannot drift silently
(WARNING 4).

Purpose: SC1's "curated corpus", and the leakage boundary that makes SC3's measured lift
trustworthy — not just non-identical, but non-contaminating (B2). NL-FEW-01.
Output: `fewshot_bank.yml` (~18-24 examples, balanced across positive difficulty classes)
and `test_fewshot_bank_disjoint.py`. This plan is independent of the engine work (Plan 01)
— it only uses the already-shipped `runner._canonical` / `_load_corpus`; the cosine
similarity-ceiling assertion additionally uses the 07-01 pinned embedding model when the
dense stack is installed and SKIPS gracefully when it is not (so this plan stays runnable
and torch-free on its own).

**Soft cross-plan coupling (documented so it isn't mistaken for a Wave-1 gap):** the
three-way disjointness + ontology-parity checks run in Wave 1 with no dependency, but the
cosine similarity-ceiling assertion imports the pinned-embedding constants that 07-01 adds
and the dense stack that 07-03 Task 1 syncs — so it will SKIP (not fail) whenever this plan
runs before the dense stack is present, and only becomes an active gate from Wave 2 onward
(after 07-03's `uv sync --extra dense` at the sweep checkpoint). This is intentional, not a
missing `depends_on`: authoring correctness (disjointness/parity) is enforced at Wave 1; the
near-clone ceiling is enforced whenever the embedder is available, at the latest before the
07-04 lift is recorded.
</objective>
