<objective>
Close NL-FEW-02: prove a measurable, statistically-supported NL→SPARQL pass-rate lift from
dense few-shot over a freshly-run zero-shot arm (paired, same session), via the Phase 6
harness — reported as a positive pass-rate lift on the 25-case conceptual-schema corpus,
NOT as an F1 number (the survey's "+21 F1" is background motivation only, never the bar — M1).

Five moving parts, all additive and gated:
1. **Critical blocker fix (RESEARCH Pitfall 2):** `OpenAICompatibleClient.generate()`
   unconditionally sends `temperature=0.1`, which gpt-5-family reasoning models reject
   with a 400 — every gpt-5/gpt-5-mini arm would hard-fail. Add a `_is_reasoning_model`
   predicate that omits `temperature` for those models. Add gpt-5-family pricing rows so
   cost accounting is not silently `$0.00` (Pitfall 4).
2. **Harness extension (RESEARCH Open Question 2 / Pitfall 5):** extend `configs.yml`
   with the 3-arm × 3-model matrix and an optional `few_shot: {mode, k}` block, and add a
   narrow additive read in `runner.py` that threads it into `NlPipeline` via the 07-03
   passthrough. `run(config_name) -> Report` stays byte-identical; `scripted` stays the CI
   default. The dense arm asserts `isinstance(index.retriever, DenseRetriever)` (D-06)
   before recording, and `BaselineConfig` gains the D-04 embedding-provenance fields.
   Add pure-Python `paired_mcnemar` / `bootstrap_paired_delta` analysis helpers (no scipy)
   that operate on two Reports' per-case verdict dicts (B1).
3. **The gated sweep runbook (D-07/D-08/D-09, redesigned per B1/M1/M2/m1/m3):** a README
   section documenting the self-baselining sweep with **N ≥ 5** runs per arm; the PRIMARY,
   PRE-REGISTERED confirmatory test = gpt-4o-mini **dense vs freshly-run zero, PAIRED**,
   passing iff **McNemar p < 0.05** (+ a bootstrap CI on the paired delta); a per-(model,arm)
   **standard-deviation** noise-floor as a SECONDARY check only; the published **~4-case
   minimum detectable effect** at n=25; the dense-vs-committed-0.32 comparison demoted to a
   SECONDARY continuity check (invalid if the resolved snapshot differs from 06.2's); the
   gpt-5-mini/gpt-5 tiers and dense-vs-bm25 reported as **EXPLORATORY** (unfiltered, never
   cherry-picked); **both** the default-install (bm25) and dense-install (dense) numbers
   reported (M3); the 07-02 nearest-neighbor bank↔corpus similarity distribution surfaced
   alongside the lift; a live model-resolution check before running (Open Question 3); and
   the MANUAL human-reviewed fold-in — run behind `RUN_EVAL=1` + `NL2SPARQL_API_KEY`, never CI.
4. **SC4 non-regression guard (M4):** the phase touches no transpiler code; add a COMMITTED
   test (`tests/w3c/test_coverage_gate.py`) that COMPUTES coverage via
   `analyze_coverage.analyze()` and ASSERTS QUERY_EVAL coverage ≥ 96.4% (FAILS on
   regression), and wire it into a REAL CI job (not the excluded/xfail-tolerant `-m w3c`
   path). Regression risk is ~nil, but the gate must ASSERT, not merely run.

Purpose: NL-FEW-02 — the measured, statistically-supported lift that justifies the whole
phase. Depends on the 07-03 wiring (dense/BM25/zero arms are only selectable once the seam +
pipeline passthrough exist).
Output: the temperature fix + pricing rows, the extended configs/runner + paired-analysis
helpers, the redesigned sweep runbook, structural + unit tests (no-network), the committed
W3C coverage-assertion gate + its CI job.
</objective>
