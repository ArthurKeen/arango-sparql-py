<objective>
Add a dense/embedding retriever to the shared NL engine (`arango_query_core.nl.fewshot`)
so both SPARQL and Cypher inherit dense few-shot retrieval. This is the engine-side
foundation of the phase — the wiring, bank, and sweep plans all consume it.

Scope is exactly four additions to `fewshot.py`, mirroring the existing `BM25Retriever`
contract wherever an analog exists:
1. `DenseRetriever` — a new `Retriever` with the lazy-import + hard-`ImportError` posture
   (per D-05 explicit-dense-mode) and a normalized-embedding cosine ranking.
2. An additive `mode=` selector on `FewShotIndex.from_corpus_files` implementing the
   two-tier degrade chain (D-05): `dense` hard-raises, `bm25` catches-and-degrades,
   `auto` tries dense→bm25→noop.
3. A public `FewShotIndex.retriever` property (D-06 belt-and-suspenders, so callers never
   touch the private `_retriever`).
4. A module-scope memoized index factory (`cached_few_shot_index`) so the
   SentenceTransformer model loads ONCE per process, not per request/per eval case
   (RESEARCH Pitfall 1).

Purpose: Dense retrieval is the SOTA-survey's #1 win (BRIEF §4). Landing it engine-side
means Cypher gets it for free. NL-FEW-01.
Output: An extended `fewshot.py`, a `[dense]` extra, and no-network unit tests. This
plan installs nothing — the actual `sentence-transformers`/`torch` install and model
download happen only in the gated sweep (Plan 04); tests here use an injectable fake
encoder.
</objective>
