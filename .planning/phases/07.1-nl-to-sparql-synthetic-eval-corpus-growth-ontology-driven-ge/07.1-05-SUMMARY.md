# Phase 07.1 Plan 05: CK25 Corporate-Domain Anchor Vendoring Summary

**Vendored CK25 (eccenca/ck25-dataset, CC-BY-4.0, 50 corporate-domain Q->gold-SPARQL pairs) and its embedded schema, then converted 49/50 surviving questions into `corpus.yml` via a manifest-driven `phys:`-annotation + D-06 filter pipeline that reuses the existing deterministic parser/resolver/translate stack -- no hand-rolled validator, no silent case drops.**

## Performance

- **Duration:** ~55 min across two sessions (process interruption mid-Task-2, resumed from committed state)
- **Tasks:** 2 completed
- **Files created:** 10 (raw/questions.yml, raw/prod-inst-schema.ttl, NOTICE.md, convert_ck25.py, test_convert_ck25.py, ontology.ttl, corpus.yml, filter_log.md, ck25/__init__.py, deferred-items.md)

## Accomplishments

- Fetched CK25's `questions.yml` (50 questions) and `graphs/prod-inst.ttl` live from `github.com/eccenca/ck25-dataset` at commit `cb928b2f201e4bdbbde9a1cd0653152779736395`; vendored the former verbatim and extracted a schema-only Turtle subset of the latter (owl:Class/owl:ObjectProperty/owl:DatatypeProperty + rdfs:domain/range only -- all instance data discarded per Open-Q2), with a compliant CC-BY-4.0 `NOTICE.md`.
- Wrote `convert_ck25.py`: loads the vendored raw files, builds `ontology.ttl` by annotating exactly the 12 classes / 13 object properties referenced by any question's `classes:`/`properties:` manifest with `phys:collectionName`/`phys:edgeCollectionName`, then applies the D-06 filter (manifest terms declared + gold parses + `translate()` yields non-empty AQL) via the repo's own `parse_sparql`/`arango_sparql.api.translate` -- reused, never re-implemented.
- Empirically confirmed 49/50 (98%) of CK25's raw questions survive the filter -- well above the RESEARCH doc's conservative ~30-45 estimate, because this transpiler already supports a broader SPARQL feature surface (SUBSELECT, GROUP BY/HAVING, aggregates, BIND arithmetic, FILTER NOT EXISTS, ASK, OFFSET+LIMIT, sequence paths, `rdfs:subClassOf*` transitive class-hierarchy paths) than assumed at planning time. The one drop (Q38) is a genuine, verbatim-recorded `UnsupportedSparqlError`.
- `test_convert_ck25.py` (TDD RED-then-GREEN) pins all four required behaviors: every kept case constructs as a valid `CorpusCase`; `ontology.ttl` resolves via `SchemaResolver.from_turtle` with every kept question's manifest term `phys:`-annotated; `filter_log` kept+dropped == total (no silent truncation); and run-to-run determinism -- plus a static `yaml.load(`-absence guard (Tampering mitigation T-07.1-02).
- `filter_log.md` records the full 50-question kept/dropped audit trail with Q38's exact rejection message.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `vendored/__init__.py` broke the Plan-02 provenance guard**
- **Found during:** Task 2, after generating `ontology.ttl`/`corpus.yml`/`filter_log.md` and running the full verification suite (`test_vendored_provenance.py` unexpectedly failed with `"__pycache__: missing NOTICE.md"`).
- **Issue:** I had created `tests/nl2sparql/eval/vendored/__init__.py` (committed in the Task-2 RED commit) so `tests.nl2sparql.eval.vendored.ck25.convert_ck25` would import as a regular package. The moment any ck25 test module got imported, Python compiled `vendored/__init__.py` into a `vendored/__pycache__/` directory -- a sibling of `vendored/ck25/` that `test_vendored_provenance.py`'s `VENDORED.iterdir()`-based dataset-directory check misidentified as an un-attributed vendored dataset (no `NOTICE.md`).
- **Fix:** Deleted `tests/nl2sparql/eval/vendored/__init__.py`. `tests/nl2sparql/eval/vendored/ck25/__init__.py` alone is sufficient -- Python 3's implicit namespace-package support resolves the `vendored` level without an `__init__.py`, and `ck25/__pycache__` (nested one level deeper, inside the dataset directory itself) is never enumerated by the guard's `iterdir()` check.
- **Files modified:** `tests/nl2sparql/eval/vendored/__init__.py` (deleted)
- **Verification:** `pytest tests/nl2sparql/eval/vendored/ck25/test_convert_ck25.py tests/nl2sparql/eval/test_vendored_provenance.py -x` -- 7 passed. Re-confirmed the namespace-package import still resolves (`python3 -c "import tests.nl2sparql.eval.vendored.ck25.convert_ck25"` succeeds).
- **Committed in:** `3f485b5` (Task 2 feat/GREEN commit)
